## 一、现在在做什么

**目标**：一个人（Silas + Claude）能独立完成一次交付——拿到业务命题，接上企业系统数据，
组装一个受治理、能自己长技能的 agent，用可复现的验收报告决定能不能上线，交付后靠回流持续
服务。同一件事做第二遍要明显更快，这是唯一标准。

**形态已定：做工作台，不做平台**，但按「将来能抽出平台」的规矩做。翻牌信号写死三条：
第三个客户 / 第一个不是自己人要用它 / 同一段东西被复制到第三处，任一命中就开始抽。

**引擎**：开源 dsh，只换 UI。交付物是一整个 agent，不是装进客户已有系统的插件。
钉死自己 vendored 的那份 dsh，不为任意版本做兼容。

**两条真实命题**：校园网客服（话术域，材料齐）、123 云盘运营（数据域，连接层齐，
`/Users/silas/B123`）。

## 五、已经定下、不要重新讨论的规矩

- **每轮交付必须在用户层面可用**（Scrum 增量）。按「FDE 能做到什么」描述一轮，不按模块。
  交付时演示一遍，并写清这一轮还不能做什么。
- **对外产物用书面专业语**，术语以 `docs/MODEL.md` 为准；内部 FINDINGS／STATUS 保留简称。
- **业务接口只允许 GET**，`/sapi/user/sign_in` 是唯一白名单 POST（登录必须 POST）。
- **凭据只记来源不记值**；真实业务数据不进仓库；报告只留结构与计数。
- **同义泛化样例只允许人工编写**，回流样本不得并入该组。
- 完整本体不做（口径登记这一薄层在 M4 内做）；业务推演引擎不做；多租户与打包不做。

## 六、我这一路犯过三次的同一个错（新会话请引以为戒）

**倾向于先做「我们已经有一半」的东西，而不是使用者顺序上的第一件。** 三次都被用户当场指出：

1. 先画界面预览，被问「用户故事地图呢？那才是预览的依据」。
2. 列了八个模块，被问「FDE 在哪儿干活？这些全是看板，没有一个是工作场所」。
3. 建议先做 M1 而不是 M0，被问「为什么不先说 M0」——而 M0 排最前的理由是我自己写的。

还有一次形态错误：交了库和脚本就说 M0 做完了，被问「页面呢？产品价值呢？」。
**增量必须是使用者拿得动的东西，不是能力。**

## 七、怎么跑

- **测试**：`./thymus/run-tests.sh`（15 files / 225 passed）
- **界面**：`bash thymus/dsh/shell.sh`，或预览工具里的 `thymus-shell`（端口 3083）。
  它用 dsh 自己的加载器起一个最小 profile：`dsh.profile.bundles` 写空，只列八个插件，
  从源码解析。**不要用 `dsh web`**——那要 dsh 的前端构建产物，本机构建过不去（见下）。
- **campus 脚本**：`DEMODIR=campus DEMO=<名字> ./thymus/demo/run.sh`，要 `.env.local` 的
  `DEEPSEEK_API_KEY`。`check-intake` 不花钱。

## 八、环境上的坑（都查过，别重查）

- `pnpm run` 会做依赖预检并触发 `pnpm install`，而仓库根的 postinstall（lefthook）在这台
  机器上失败——dsh 是 submodule，它的 git config 里有 `core.worktree`。绕法：先跑一次
  `pnpm install --ignore-scripts`。**不要去改用户的 git 配置。**
- `tsc -b` 是增量的，被中断过会留下 `.tsbuildinfo` 让它什么都不输出，需要 `--force`。
- `dsh web` 要前端 dist，而 `pnpm run build` 在 tsdown 那步失败：它把仓库根当成构建目标，
  而根包没有 `src/`，那个入口永远不存在。试过 workspace include/exclude、`-F` 过滤、
  `workspace: true`、以及照 `dev-web.ts` 用 JS API 传目录列表，四条路都不通。
  **这是 vendored dsh 自己的构建问题，不要靠伪造产物绕过去。**
- 用户的 `~/.dsh/profiles/headless` 里挂着一个没装的插件；要用 headless 就换临时 `DSH_HOME`。
