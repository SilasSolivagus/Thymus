# 对象与状态定义

> 这份文档是防漂移的契约。工作台的每个界面、每条命令、每份报告都只使用这里定义的对象、
> 字段与状态词；需要新概念时先改这份文档，再改实现。
> 定稿 2026-08-25，随实现修订，修订要写明动机。

## 0 · 术语

界面、报告、文档统一使用下列词。括号里是内部曾用的简称，仅保留在 FINDINGS／STATUS 与代码
注释中，不进入对外产物。

| 术语 | 含义 |
|---|---|
| 实例 | 一个客户一套：约束声明、连接器、技能、样例集、验收记录各自独立 |
| 约束声明 | 客户 SOP 中的条款写成的数据表，是交付物本体 |
| 应拦截样例（必拦） | 明确违反某条约束的输入，验收时必须被拦住 |
| 应放行样例（必放） | 完全合规的正常业务话术，被拦即为误拦 |
| 同义泛化样例（留出） | 语义同类、字面与声明不重叠的说法，判别力来源，仅限人工编写 |
| 未覆盖条款（uncovered） | 内置类型表达不了的条款，必须登记，不得省略 |
| 冻结 | 一次验收全部通过后，把声明与样例集固化为带哈希的产物 |
| 替代话术 | 某条约束拦下后改说的固定话术 |
| 兜底话术 | 网关最后使用的替代话术，退无可退，必须在所有约束下无冲突 |
| 技能 | agent 可调用的一个受治理动作，对应一个外部接口或本地能力 |
| 回流样本 | 线上或影子运行中出现、需要人工判定的输入与响应 |
| 连接器 | 一个企业系统的接入方式：地址、认证、续期、已确认接口 |
| 口径条目 | 一个指标或字段的算法与来源定义，用于消除同名不同义 |
| 业务指标 | 本次交付对业务方负责的结果指标，含基线与目标 |
| 产出物 | agent 定期生成并投递的东西：日报、预警、看板 |

判定结论只用三个词：**未拦截**（该拦没拦）、**误拦**（该放被拦）、**判定不稳定**（同一样例多轮
结果不一致）。

## 1 · 对象

### 1.1 实例 Instance

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 目录名，全局唯一 |
| name | string | 显示名 |
| domain | `话术` \| `数据` | 决定默认可用的约束类型与技能形态 |
| specVersionId | ref | 当前生效的声明版本 |
| connectorId | ref? | 数据域实例的连接器；话术域可空 |
| skillPolicy | object | 配额上限、审批人、允许的接口前缀 |
| outcomeMetrics | OutcomeMetric[] | 本次交付负责的业务指标，见 1.10。**不得为空** |
| createdAt | timestamp | |

**不变量**：实例之间不共享技能实例与凭据；任一实例的声明或技能变更不得影响其他实例。

### 1.2 声明版本 SpecVersion

交付物本体。**一次冻结对应一个不可变版本**，声明文件内容变化即产生新版本。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | |
| instanceId | ref | |
| contentHash | sha256 | 声明文件内容哈希，用于判定是否需重验 |
| status | 见状态机 | |
| constraints | Constraint[] | 见 1.3 |
| uncovered | UncoveredClause[] | 未覆盖条款，条目含条款原文与不能覆盖的原因 |
| owner | string | 责任人 |
| frozenAt | timestamp? | |
| revalidateBy | date? | 复验期限，到期转「需重验」 |
| artifactPath | path? | 冻结产物，仅在已冻结时存在 |

**状态机**

```
草稿 ──自检通过──> 待验收 ──验收通过──> 已冻结
  ^                   │                   │
  └────自检不通过──────┘                   │
  ^                   ^                   │
  └────验收不通过──────┘                   │
                                          │
已冻结 ──声明变更 / 样例并入 / 模型变更 / 到期──> 需重验 ──> 待验收
已冻结 ──被新版本取代──> 已归档
```

**不变量**：只有「已冻结」的版本允许上线；`contentHash` 与冻结产物不一致时立即转「需重验」。

### 1.3 约束 Constraint

| 字段 | 类型 | 说明 |
|---|---|---|
| name | string | 归因用，出现在拒绝理由里，实例内唯一 |
| type | enum | 五种内置类型之一（字面禁语／语义策略／字段抹除／调用前置／越界兜底） |
| body | object | 按类型而定的规矩内容 |
| replacement | string? | 该约束的替代话术；无则使用兜底话术 |
| samples | SampleSet | 见 1.4 |

### 1.4 样例集 SampleSet

| 字段 | 类型 | 说明 |
|---|---|---|
| mustBlock | Sample[] | 应拦截样例，不得为空 |
| mustPass | Sample[] | 应放行样例，不得为空 |
| generalization | Sample[] | 同义泛化样例，不得为空 |

每条样例：`{ text, origin: 人工编写 | 回流并入, addedAt, sourceSampleId? }`

**不变量（来自实测结论，违反会使验收失去意义）**：
- 同义泛化样例**只允许人工编写**。回流样本不得并入这一组——出题方看得到的信息与被测方同源，
  并进去之后测的是记忆而非泛化。
- 同一条文本不得同时出现在应拦截与应放行两组。
- 同义泛化样例不得与任一应拦截样例逐字相同，也不得直接包含声明中已列举的词。

### 1.5 验收运行 AcceptanceRun

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | |
| specVersionId | ref | |
| rounds | int | 重复轮数，默认 3 |
| model | string | 判定所用模型 |
| criteria | object | 四条判据各自的结果，见下 |
| verdict | `通过` \| `不通过` \| `运行失败` | |
| issues | Issue[] | 见 1.6 |
| reportPath | path | |
| startedAt / finishedAt | timestamp | |

**四条判据**（缺一不可，全部通过才允许冻结）：

| 判据 | 通过条件 |
|---|---|
| 样例完整性 | 三组样例齐全，且不违反 1.4 的不变量 |
| 兜底话术无冲突 | 兜底话术在所有约束的触发语境下均不违规 |
| 拦截正确性 | 应拦截样例全部拦住，应放行样例无一误拦 |
| 判定稳定性 | 各轮结果一致 |

### 1.6 验收问题 Issue

| 字段 | 类型 | 说明 |
|---|---|---|
| kind | `未拦截` \| `误拦` \| `判定不稳定` \| `兜底冲突` \| `替代话术降级` \| `未覆盖` | |
| severity | `阻断` \| `提示` | 阻断项使验收不通过；提示项记录但不阻断 |
| constraintName | string? | |
| sampleText | string? | |
| detail | string | 面向人的说明，写清「是什么」与「要改什么」 |
| status | `待处理` \| `已处理` \| `已接受` | 「已接受」表示计入已知限制，需写明理由 |

**级别规则**：`替代话术降级`（某条约束的替代话术在别的约束下不成立）为提示——运行时会退到
兜底话术；`兜底冲突` 为阻断——兜底话术退无可退。

### 1.7 技能 Skill

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | |
| instanceId | ref | |
| name | string | 工具名，实例内唯一且不可改名 |
| endpoint | string | 接口路径或本地能力标识 |
| method | `GET` | 业务接口只允许 GET；登录是连接器内部行为，不作为技能暴露 |
| params | object | 参数形状 |
| returns | object | 返回形状 |
| purpose | string | 用途，由提出方填写 |
| risk | string | 风险标注，例如「返回含合作方名称」 |
| proposedBy | `人工` \| `agent` | |
| approvedBy | string? | |
| status | 见状态机 | |

**状态机**

```
待审批 ──批准──> 已启用 ──回收──> 已回收
   │
   └──拒绝──> 已拒绝（终态，理由回传提出方）
```

**不变量**：
- 非 GET 的业务调用在工具层直接拒绝，不依赖 agent 自觉，且有绕过测试。
- 「已启用」以外的状态一律不可调用。
- 新启用的技能自动纳入该实例的字段治理与回流，不存在脱管技能。
- 技能名不可复用：已回收的名字不得被新技能占用。

### 1.8 回流样本 ReturnedSample

| 字段 | 类型 | 说明 |
|---|---|---|

| source | `线上` \| `影子运行` | |
| input | string | 用户输入 |

### 1.9 连接器 Connector

整合墙是多数交付真正的失败点，连接器是跨客户可复用的第一类资产。

设计要点是**把接入拆成三层，因为三层的性质不同**：接入层每个系统只做一次、只能人工；
接口登记是数据不是代码；技能由登记表自动生成。加一个接口应当是**加一行加一次确认**，
而不是写一段代码——手写连接器的问题不是慢，是第十个接口和第一个接口一样费劲，不复利。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | |
| instanceId | ref | |
| systemType | string | 系统型号（如某款 ERP、某个自研管理后台）。**登记表按型号归档，不按客户** |
| kind | `api` \| `db` \| `file` \| `browser` | 接入档位，见下方降级阶梯 |
| baseUrl | string | |
| auth | object | 认证方式与**凭据来源**：环境变量名或密钥管理条目，不记凭据值 |
| renewal | object | 续期策略，例如 401 后重新认证 |
| discovery | string | 接口发现方法的记录，供同型号系统复用 |
| accessLevel | `只读聚合` \| `只读明细` \| `可写` | 当前已获批的权限档，见下 |
| endpoints | Endpoint[] | 接口登记表 |

**Endpoint**：`{ path, method, params, returns, confirmedBy: 抓包 | 文档 | 推测, sample?, addedAt }`

**降级阶梯**：没有接口时按 `api → db → file → browser` 依次降级——数据库只读副本最干净，
定时导出文件最稳，浏览器自动化最脆且会被改版打断。**四种 kind 在下游必须一致**：技能不感知
数据来自哪一档，否则降级就会污染上层。选用 `browser` 时须在验收报告中写明其脆弱性。

**权限按档推进**：`只读聚合 → 只读明细 → 可写`，每档单独申请与审批。只读接入的审批阻力
低一个量级，能让交付在第一周拿到数据。**本期只做到「只读明细」。**

**不变量**：
- 业务接口的 `method` 只能是 GET；认证所需的 POST 属连接器内部行为，不进入 `endpoints`，
  也不暴露为技能。
- 凭据只记来源，不记值。客户现场必须使用**服务账号**并由**客户自己的密钥管理注入**；
  FDE 不持有长期凭据。个人账号会因离职、改密、网络策略而失效，且责任不清。
- `confirmedBy` 为「推测」的接口不得生成技能——未经确认的返回形状会让下游治理失效。
- 跨客户可复用的是**发现方法与系统档案**，不是具体接口；`systemType` 相同即可套用。

### 1.13 前置登记 Intake

现场前提的登记表。**判断留给人，事实进系统，系统据此收窄自己允许做的事**——与把 SOP 条款
变成声明是同一个动作，只是对象换成了现场前提。每个实例有且只有一份。

| 字段 | 类型 | 说明 |
|---|---|---|
| dataEgress | `允许` \| `禁止` \| `仅私有模型` | 业务内容能否发给外部模型 |
| allowedModels | string[] | 允许使用的判定模型 |
| logRetention | string | 日志留存与调阅要求 |
| systems | { name, systemType, accountType, accessLevel, approvedBy, approvedAt }[] | 已获批的系统与权限档 |
| stakeholders | { role, name }[] | 决策人、业务责任人、数据责任人、安全对接人 |
| materials | { title, version, providedBy, receivedAt }[] | 材料来源清单 |
| channel | string? | 对话入口渠道 |
| rollout | object? | 切流计划与培训对象 |

**这张表反过来约束系统**：

| 登记的事实 | 系统的行为 |
|---|---|
| `dataEgress = 禁止` | 语义类约束标为不可用；声明只允许使用确定性类型（字面禁语、字段抹除、调用前置）。**这是范围前提，不是功能缺口** |
| `allowedModels` 与既有验收所用模型不一致 | 已有的判定数字全部作废，须重新验收 |
| `accessLevel = 只读聚合` | 明细类技能不得生成 |
| `materials` 缺失 | 引用该材料的约束在冻结时告警——来源不可追溯 |
| `stakeholders` 空缺 | 无法指定复验责任人，声明不得冻结 |

**不变量**：语义类约束的冻结，必须以 `dataEgress ≠ 禁止` 且判定模型在 `allowedModels` 内
为前提。

### 1.14 积累视图 AssetLedger

派生视图，不独立存储。统计口径：约束类型数、可复用声明模板数及复用次数、连接器数及复用
次数、口径条目数、技能数、样例集总条数、已记录的实测结论数、跨实例复用项。

**回流计量**：每次交付结束时统计有多少东西沉淀回工作台（模板、连接器、口径、表达族、
审批先例）。行业口径是每次交付至少一件；连续两次为零即说明在做一次性项目而非积累。

## 2 · 跨对象不变量汇总

1. 只有「已冻结」的声明版本可以上线。
2. 声明内容哈希与冻结产物不一致 → 立即「需重验」。
3. 业务接口只允许 GET；凭据不进提示词、日志、会话记录与仓库。
4. 真实业务数据不进仓库；报告只保留结构与计数。
5. 同义泛化样例只允许人工编写。
6. 技能未经批准不可调用；无脱管技能。
7. 实例之间不共享凭据与技能实例。
8. 业务接口的方法只能是 GET；认证 POST 属连接器内部行为，不暴露为技能。
8b. 凭据只记来源不记值；客户现场用服务账号、由客户密钥管理注入，FDE 不持有长期凭据。
8c. 未经确认（`confirmedBy` 为推测）的接口不得生成技能。
9. 数值类约束引用的指标必须已登记且为「已确认」，否则不得冻结。
9b. 语义类约束的冻结以「数据可出境且判定模型在允许清单内」为前提；不满足则该类约束不可用。
10. 每个实例必须至少声明一项业务指标。
11. 产出物内容与对话同样受说话通道治理。

## 3 · 命名与状态词对照（实现必须照用）

| 概念 | 状态词 |
|---|---|
| 声明版本 | 草稿 / 待验收 / 已冻结 / 需重验 / 已归档 |
| 验收运行 | 运行中 / 通过 / 不通过 / 运行失败 |
| 验收问题 | 待处理 / 已处理 / 已接受 |
| 技能 | 待审批 / 已启用 / 已拒绝 / 已回收 |
| 回流样本 | 待标注 / 已标注 / 已并入 / 已丢弃 |
| 口径条目 | 待确认 / 已确认 / 有争议 |
