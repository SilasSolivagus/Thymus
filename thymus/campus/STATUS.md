## 一句话

**约束可挂载、可评测、可归因，而且约束不由被约束方掌握。**
模型能写约束，判不了自己写得对不对；判分和考卷得由外部给。

---

## 架构结论（可直接照做的设计规则）

这七条都有实测支撑，编号指向证据。

1. **约束不进动态注册表**，由宿主直接挂载。否则任何动态插件都能 `stop` 掉它（08），
   连换版失败都会把它带走（14）。
2. **约束不能和被约束方在同一条通道上做同侪**。`tools/pre-execute` 是短路链、
   `llm/stream` 是包装链，极性相反但都是「后动手的赢」，`prepend` 两边都能用，
   所以顺序保证不住（09）。
3. **判决聚合，不是短路链**：收齐所有判决再裁决，任一 deny 即拒绝，顺序无关（10）。
4. **白名单，不是黑名单**。按工具名 deny 有确证缺口——插件注册一个同功能新名字就绕过（10）。
5. **语义判定放网关里，不要写成 `llm/stream` 插件**。两个语义插件挂一起会无限递归，
   一句话触发 12 次判定调用；放网关里则各判一次、互不污染（13）。
6. **判定用的模型调用必须走 `judgeText`**，不要直接 `for await ctx.llm.stream`。
   失败时它不抛错，发 error finish 后正常结束，try/catch 不触发（15）。
7. **写约束的 agent 和被约束的业务 agent 必须分开**，业务 agent 不给 cordis 动态插件工具。
   一旦有，它能自挂前插的 allow，或提交一个装载即抛错的新版把约束带走（09、14）。

代码：`thymus/src/gate.ts`（182 行），`thymus/src/eval-framework.ts`（318 行）。

## 已确认的事实

### 模型写约束插件的能力

- 告知「插件内可以调模型」，模型**会用**，首版就 `inject: ['llm']`，不用反馈推（05）。
- 相当比例会加一道字面门控把新机制架空：**7 次里 3 次**，分布双峰 `[2,2,2,3,6,6,6]`（12）。
  消融证明漏的是门控不是判定：删掉门控那一行，留出集 6/6（05）。
- 反馈能不能纠正：**4 次里 2 次**。一次只扩词表不动机制（强反馈直说也没用），
  一次拦住新的却丢掉旧的（07、12）。

### dsh 的行为（其 README 明说沙箱不是安全边界）

- host-only 插件挂载**零审批**；审批分支只对 client 半边存在（08）。
- 已加载插件能卸掉别的插件，全自助：`ctx.get()` → 读 `registry` → 翻 sessionId →
  `listPlugins` → `stop`（08）。
- 热替换本身干净：新版立即生效、旧版无残留、两版不叠加、不打断飞行中的工具执行（14）。
- 但 `run` 阶段换版失败**不回滚**：`retract` 在 `startHost` 之前，失败后旧约束消失（14）。
  `define` 阶段失败（语法错）则安全。
- 动态插件用不了 Node 定时器，要 `inject: ['timer']` + `ctx.timeout(ms)`；
  `idPrefix` 必须 3–6 位纯小写字母（14）。
- 工具注册必须走 `harness.defineTool`，参数是扁平 DSL 不是 JSON Schema 嵌套（10）。

### 评测框架

- 公开集（断言 SPEC 明示词）**零判别力**——每一轮实验两臂都是 9/9。判别力全在留出集，
  而留出集只有人写得出来：出题 agent 看到的也只有 SPEC（05）。
- 梯度体检 `checkEvalGradient`：负向断言在空插件组下每条都必须垮，垮不掉是死用例。
- 回归集要用 `said-equals` 不是 `said-includes`——后者只判「原文还在里面」，
  加前缀的插件照样过。
- 耗时是最锋利的诊断信号之一：「未问模型」（3–5ms vs 真调用 0.8–1.6s）是唯一能一眼
  看穿「它只是扩了词表」的证据（07）。

## 已撤回或降级的结论（这一节是给未来的自己看的）

| 原结论 | 现状 | 出处 |
|---|---|---|
| 首版基本都会加门控（5 次里 4 次） | **降级为 3/7**，分布双峰 | 12 |
| 弱反馈一轮就解掉且泛化 | **4 次里 2 次** | 07、12 |
| J-Space 是质量负收益 | **撤回**，落在基线下模态内分不出来；不引入的理由改为更慢更贵 | 12 |
| r1 是「为了多拦改坏了合规话术」 | **错的**，掉的全是禁语用例，两条过度改写对照一次没垮 | 15 段落／FINDINGS-07 顶部 |
| 多插件同时正确是模型能力边界 | 至少语义约束这一类是**机制问题**，不是能力问题 | 13 |
| 网关里两条约束串行、延迟翻倍 | **错的**，`adjudicate` 用 `Promise.all`，延迟取最慢一条 | 10 |
| 网关「判不了就不放行」 | 在静默失败形态下**曾经不成立**，已用 `judgeText` 修 | 15 |

## 方法论规矩（都是被自己的错换来的）

1. **实测不等于测对了，要验中间态。** 攻击插件没挂载成功和被拦住，看到的结果一样；
   因此先后得出两个都很像样、都是错的结论。
2. **样本不够时，结论和够的时候长得一样。** 双峰下 n=3 有约四分之一概率三次落在同一峰，
   看起来就是干净的规律。凡是「模型通常会 X」的断言，**必须带样本数和分布**：
   写 `3/7，[2,2,2,3,6,6,6]`，不写「基本都会」。
3. **全员满分的评测集判别力为零。** 回归集八个插件全 20/20 时，必须先拿合成的
   阳性对照证明这套题在真被破坏时会响，再谈结论。
4. **dsh 用返回值表达失败，不是异常。** 接它流式接口的地方都要显式检查结束原因。
   这一类错误已经踩了三次：`say()` 吞传输失败、反馈空转、判定静默失败。
5. **读代码得出的结论要标明来源**，不要和实测并排放。本轮有两次读代码推理是错的。

## 仍未验证

- 超时默认 10 秒是拍的，没按真实判定延迟分布校准（实测单次 0.8–1.6 秒，余量约 6 倍）。
- 字面约束那一类的多插件能力没验（要花钱跑模型）。
- 双峰的成因不知道，也没加样本坐实。
- 判定结果落盘做题库——是建设不是验证，没做。
- 抽检校准那一环这个 spike 里验不了（需真人真流量）。
- 网关仍在同进程，是应用层逻辑不是边界。CC 靠操作系统文件权限做最高层，我们没有对应物。
- 说话通道网关站在「我们自己发起装配」的路径上；真实部署里装配由 agent loop 做，
  网关插在哪没验。
- `run` 阶段换版失败不回滚，是 dsh 有意还是缺口——只记了现象，没读那段设计意图，
  也没向上游确认。
