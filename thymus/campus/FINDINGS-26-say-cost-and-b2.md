# 发现 26：说话侧的两个数，与 B 缺口的补法

两件收尾。一件是量数（`probe-say-cost.ts`，脚本化 adapter，不花钱），
一件是补上发现 21 登记的那条「表达不了」。

## 一、缓冲全流的代价：首字延迟等于整段生成时间

上游按 12 个 delta、每个间隔 40ms 发（整段约 480ms），各跑 3 次：

| | 首字 | 整轮 |
|---|---|---|
| 无网关 | 6 · 4 · 2 ms（均 **4ms**） | 410 · 406 · 407（均 408ms） |
| 装网关（裁决不调模型） | 404 · 402 · 404 ms（均 **403ms**） | 404 · 402 · 404（均 403ms） |

**首字延迟从「第一个 delta」变成「整段结束」**，整轮耗时基本没变（403 vs 408ms，
机制本身的开销可忽略）。

这是必须付的代价，不是实现不好：agent loop 每收一个 chunk 就落一条 `assistant/chunk`，
先放行再改就晚了——事件已落库、流式 UI 已经渲染过（发现 17）。要么整段裁决，
要么放弃「改写对用户不可见」。

**还要加上裁决本身的延迟**：这一轮用的是不调模型的约束。语义判定另有数——
A2 单跳约 967ms，D 两跳 0.7–3.7 秒。所以一句话的真实首字延迟大约是
「整段生成时间 + 1～4 秒」。

一条现成的省法在实现里已经有了：`require-before-say` 的事实成立时直接放行、不问模型，
所以正常会话里认过人之后的每一句都不额外花钱（论证126）。

## 二、多 agent 并发：不串

一个宿主两个 agent 同时说话，甲的话合规、乙的话有禁语：

```
甲说的：甲会话的正文：账期是2026年8月。      ← 原样
乙说的：抱歉，我需要转人工。                  ← 被改写
裁决看到的（用户那句 ／ 待判正文）：
  我是乙 ／ 乙会话的正文：这个不可能。
  我是甲 ／ 甲会话的正文：账期是2026年8月。
上下文与正文配对正确：true
```

裁决顺序是交错的（乙先于甲返回），但每次裁决拿到的对话和待判正文都是同一个会话的。

## 三、B 缺口补上了：`require-before-say`

发现 21 里登记的第一条「表达不了」是：SOP 原文管的是「未认人不得**回复**账号相关内容」，
而内置类型只能按工具名判前置，判不了「这段话是不是在讲账号详情」。

新类型把两样合起来——事实从会话日志现读（`require-before` 的来源），
内容交给判定器（`require-fallback` 的上下文判定）：

```ts
{
  type: 'require-before-say',
  requires: 'lookup_account',              // 会话事实
  topic: '具体账号的账期、费用、账号详情',    // 什么算受限，照抄条款
  reply: '麻烦您先提供一下学号、手机号码，这边为您查询。',
}
```

它跟 `require-before` 是一对：那条拦「未认人不许**去查**」，这条拦「未认人不许**说出来**」。

判定顺序是省钱的关键，也是设计上的要点：**事实成立就直接放行，不问模型**。
只有事实不成立时才花一次调用去判这句话讲没讲受限内容。

为此 `SayContext` 多了 `caller`：说话侧只在 `stream(options)` 拿得到 sessionId
（`prepareCall` 的 config 里没有，发现 18 实测过），会话日志顺着 agent 注册表回查。
注册表没装就没有身份——不编一个空的顶上，要它的约束据此拒绝（论证128）。

那份真实 SOP 的声明因此从 6 条变成 7 条，`uncovered` 从 3 条减到 2 条，机械体检通过。

新类型的 `compileOne` 分支我第一次插错了地方——落进了 `probesOf`，因为两个函数里有
一模一样的一行 `if (spec.type === 'require-fallback') {`。类型检查当场报出来，
没有流到别处。**按位置替换文本时，锚点得在函数内唯一。**

## 没验的

- 首字延迟只在脚本化 adapter 上量。真模型的分块节奏不同，但结论的形状不会变
  （首字 = 整段结束），变的是那个绝对值。
- 并发只测了两个 agent、各一句话。
- `require-before-say` 只用假判定器验了机制与用例，**没在真模型上跑过留出集**——
  按 D 类的教训（发现 20），机制通不等于判定器判得住。这是下一步。
- 判定器只看到这一句话，看不到用户问了什么。「用户主动报了学号」这类事实还是要靠
  工具调用留下痕迹，光靠对话正文判不了。
