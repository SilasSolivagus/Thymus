# 发现 12：基线是双峰的，n=3 分不出来——发现 05、07、11 三条结论都要降级

发现 11 跑出三次基线首版全部没加门控、留出集2 全 6/6，与发现 05/07 记的
「首版基本都会加门控（5 次里 4 次）」差得离谱。查完了，是方差。

## 排查过程

**提示词逐字相同。** `a2-ab.ts` / `a2-feedback.ts` / `a2-jspace.ts` 三个脚本的
`SPEC_A2`、`CHANNEL_SAY`、`CHANNEL_LLM` 三个常量 MD5 一致；`submit_plugin` 的描述在
`a2-feedback` 与 `a2-jspace` 之间完全一样。排除提示词差异。

**耗时同量级，排除环境变化。** 从落盘轨迹的时间戳算首轮时长：发现 07 是
332/485/384 秒，发现 11 基线是 362/408/326 秒。原先怀疑「模型变慢、思考变多」，
不成立。

剩下的只有运行方差。

## 把所有基线首版样本汇到一起

从 `submitted/*.json` 取，不凭记忆：

| 样本 | 留出集2 | 未问模型 |
|---|---|---|
| 发现06 v1 | 2 | 5 |
| 发现07 r1 v1 | 2 | 0 |

基线首版留出集2 全样本（n=7）：**[2, 2, 2, 3, 6, 6, 6]**——明显双峰，
一簇在 2–3，一簇在 6。没有中间值。

基线首版「加了门控」（未问模型 > 0）：**3/7**，不是「5 次里 4 次」。

## 要改的三条

### 发现 05／07：「首版基本都会加门控」降级

正确说法是 **7 次里 3 次**，约四成，不是「基本都会」。原来那个 4/5 的计数把发现 05 的
arm on 也算了进去，而它没有测留出集2，判据不同；剩下的样本量也不足以支撑「基本」二字。

这条我在对外讲「自生长限制」时用过，说「模型第一版一定会加一道词表筛选」——那句话错了。

### 发现 11：J-Space 的「质量负收益」不成立

J-Space 臂留出集2 是 **[1, 2, 2]**，落在基线下模态 **[2, 2, 2, 3]** 里面。
3 对 3 那次看着「无重叠」，是因为那一批基线恰好三次都落在上模态。**分辨不出来。**

**仍然成立的是效率那一侧**（同批 n=3 对 n=3，两组都无重叠）：

```
输出 token   基线 [91974, 101660, 116860]  |  J-Space [130982, 148152, 211380]
dev 耗时(s)  基线 [326, 362, 409]          |  J-Space [488, 506, 761]
```

所以结论「不引入」仍然成立，但**理由要改**：不是因为它让质量变差（分不出来），
是因为它明显更慢更贵，而质量上看不出任何好处。它自报的 2.53× 提速、2.21× token
下降，在我们这个基准上一次都没出现过。

## 方法层面的账

这一轮真正的教训不是「基线会变」，是**我们的样本量一直不够，而不够的时候结论看起来
和够的时候一模一样**。

- 双峰分布下，n=3 有约 1/4 的概率三次全落在同一峰上，看起来就是一条干净的规律。
- 发现 07 已经因为 n=1 推翻过发现 06 一次。这次是 n=3 推翻 n=3。
- 判据本身没问题——留出集确实测出了差异；出问题的是**拿几个样本就下「基本都会」这种
  频率断言**。

可操作的规矩：**任何形如「模型通常会 X」的断言，样本数和分布要一起写出来**，
写成 `3/7，分布 [2,2,2,3,6,6,6]`，不写「基本都会」。分布贴出来，读的人自己能看出
能不能信。
