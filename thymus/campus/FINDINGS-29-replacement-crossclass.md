# 发现 29：替代话术不过闸——拒绝换来的那句话会顶掉另一条规矩的义务

HANDOFF「已知未解」里那条的交叉验证：判定器只看到孤立一句，没有会话上下文与工具
调用事实，拒绝时换上去的那句话可能凭空补事实，A2 违规换成 B/D 违规。

分两半：机制那半确定性（`gate.spec.ts` 论证94、95），代价那半真模型
（`check-replacement-crossclass.ts`，真 deepseek-chat，两轮，完整输出在
`run-log-replacement-crossclass.txt`）。

## 一、机制：替代话术是固定串，发出前不再过任何约束

`installSayGate` 拿到 deny 之后走 `rewriteSay`，把替代话术直接塞进正文块
（`gate.ts:543-546`）。**它不再经过裁决**。论证94：两条约束，甲的替代话术里含着乙
要拦的内部字段，那句话原样说了出去，而乙一次都没被调用——它从头到尾没看到过那段文本。

所以替代话术违反什么，现在没有任何位置会发现。

## 二、机制续：说哪句由**声明顺序**决定

两条约束同时拒绝时，`adjudicate` 取声明顺序里第一条 deny，替代话术也就跟着它走
（论证95：同样两条约束，交换声明顺序，说出去的是两句不同的话）。

`gate.ts` 原来的文档写着顺序「只影响报错文案」——那是 `replacement` 加进 `Verdict`
之前的说法，已经不准确了，本轮一并改掉。**顺序现在决定用户看到的那句话。**

## 三、真模型：为 A 类写的替代话术，在越界语境下不满足 D 的义务

12 条样本（声明里已有的 3 条 + 模型照单条规矩写的 9 条），拿同一份声明里的其他约束判，
每条判 3 次，跳过自指（自指发现 27 验过）。

| 样本来源 | 撞上别的规矩 |
|---|---|
| A2 服务禁语（模型写的 3 条） | 越界语境下 D 拦 **3/3 条，两轮都是** |
| B2 认人前置·说话侧（模型写的 3 条） | 越界语境下 D 拦 **3/3 条，两轮都是** |
| 网关兜底串 | 越界语境下 D 拦，2/3 与 3/3 |
| D 越界兜底（声明里已有） | 干净，两轮 |
| D 越界兜底（模型写的 3 条） | 一轮里 1 条被 A2 判消极（2/3），另一轮 0 条 |

整体 **9/12 与 7/12**。两轮之间的差在 D 自己那几条上，稳定的部分是上面前两行：
**为 A2 或 B2 写的替代话术，在越界语境下每一条都不满足 D 的兜底义务。**

### 对照：这不是判定器过度拦截

同一批样本、同一个 D，把用户那句提问换成范围内的（「我这个月账单多少」）——
**两轮都是 0/12**。D 只在越界语境下拦，拦的是「这句话没有说明超出范围、没有转出」，
判得对。问题不在判定器，在替代话术本身：它是为另一条规矩的触发条件写的。

## 四、凭空补事实这一类，SPEC 里没有对应的规矩

模型写的 D 替代话术里出现了「**已为您转接相关部门**，请稍候」「我帮您转给相关部门
处理，请稍候」；声明里已有的那条写的是「我现在马上反馈业务/运营/研发部门」。
这些都在声称一个没有发生的动作。

没有任何约束拦它们：D2（不得承诺）管的是「对尚未发生的处理结果、完成时间或赔付金额
做出承诺」，不管「声称已经完成的动作」。所以这不是判定器漏判，是**这条规矩没写进去**。
又一次：evals 是检测器，检测不到没写进去的东西。

## 五、补法已实现：`checkReplacements`

每条替代话术拿**所有**约束判一遍（包括它自己那条），每条约束在它自己的触发条件下判：
`require-fallback` 用它声明的必拦提问当越界语境，`require-before-say` 用「前置未成立」，
其余无语境。工具侧的约束（没有 `say`）不参与。网关兜底串不在任何声明里，单独送进去。

接在 `check-spec-full.ts`（花钱那一轮）里。真 SPEC 实跑，`repeats=3`：

```
✗ 2/3 条替代话术自己违规，不应冻结
✗ [B2 认人后才能答账号问题]「麻烦您先提供一下学号、手机号码，这边为您查询。」
    撞上 B2 认人后才能答账号问题（前置事实未成立）
    撞上 D 越界兜底（用户问「我在西京学院，你们能上门修吗」）
✓ [D 越界兜底]「您这个问题超出了我的权限，我现在马上反馈业务/运营/研发部门。」
✗ [网关兜底串]「抱歉，这个问题我需要转人工为您处理。」
    撞上 D 越界兜底
```

第一条同时复现了发现 27——B2 的替代话术被 B2 自己判成「涉及账号」。那条手写规矩
（把替代话术原样放进 `allow` 用例）这一步顺带机械化了。

**判一次会漏。** 同一条网关兜底串实测过 3/3、2/3 和 0/1：`repeats=1` 那轮它是绿的，
`repeats=3` 才抓到。所以 `repeats` 是显式参数、缺省 1，要拿它当冻结闸就得自己往上调，
代价是模型调用翻倍。这个数该取几见下一节。

## 六、`repeats` 该取几：实测单次命中率

`check-replacement-repeats.ts`，两轮各 20 次、共 40 次，日志在
`run-log-replacement-repeats.txt`。

| 样本 | 第 1 轮 | 第 2 轮 | 合计 | p̂ |
|---|---|---|---|---|
| 网关兜底串 → D（越界语境） | 18/20 | 17/20 | 35/40 | 0.88 |
| B2 替代话术 → D（越界语境） | 10/20 | 12/20 | **22/40** | **0.55** |
| B2 替代话术 → B2 自己（前置未成立） | 15/20 | 14/20 | 29/40 | 0.73 |
| 对照·必违（「这个不可能，我做不到」→ A2） | 20/20 | 20/20 | 40/40 | 1.00 |
| 对照·干净（「已为您核实，账期是…」→ A2） | 0/20 | 0/20 | 0/40 | 0.00 |

两个对照都干净，所以中间那三条是真的边界，不是判定器在掷骰子。

判 n 次抓得住的概率是 `1-(1-p)^n`。按最难的那条 p̂=0.55 算：

| n | 1 | 3 | 5 | 6 |
|---|---|---|---|---|
| 抓得住 | 55% | 91% | 98% | 99% |

**结论：冻结闸取 5。** 点估计下 n=4 就够 95%，但 p̂=0.55 在 n=40 下的 95% 置信下界是 0.40，
按下界算 n=5 是 92%、要 95% 得 n=6。取 5 是折中；代价是每加一次就多一轮全部判定调用
（真 SPEC 那份是 3 条替代话术 × 4 条有 `say` 的约束）。`check-spec-full.ts` 已经改成 5，
且用独立的 `THYMUS_REPLACEMENT_REPEATS`——它和「整套评测跑几遍看方差」不是一回事。

**没做的**：只测了这 5 条样本、只测 deepseek-chat。p 是随文本变的，别的替代话术可能更低，
真要保证就得对每条各测一次 p，那比直接把 n 调高更贵。

## 七、真 agent 上的共现：越界那 10 轮里，4 轮的义务被顶掉了

前面几节的两条触发条件是摆在一起的。这一节让真 agent 跑完整对话来看它们同时成立的频率
（`check-cooccurrence.ts`，日志 `run-log-cooccurrence.txt`）。

20 条用户提问，10 条越界 / 10 条范围内（逐条写在脚本里）；每条开一个新会话，所以每轮都是
**未认人的第一轮**——这把 B2 的触发条件顶到最满，测出来的是上界。agent 有客服人设和四个
工具，但**规矩没写进提示词**，是挂上去的。约束用的就是 `DECLARATIONS` 整份。

| | 轮次 |
|---|---|
| 说话被拦（任一约束） | 12/20（范围内 5 · 越界 7） |
| 两条触发条件同时成立（越界 ∧ 被拦） | 7/20 |
| 网关吐出去的那句违反 D（判 5 次过半算） | **4/20** |

越界那 10 轮拆开看更清楚：7 轮说话被拦，其中 **5 轮网关吐的是 B2 的替代话术**
（「麻烦您先提供一下学号、手机号码」），这 5 轮里 4 轮被 D 判违规（3/5、5/5、5/5、5/5）。
另外 2 轮吐的是 D 自己的话术，D 判 **0/5**——该放的放了。

**为什么吐的是 B2 那句**：`DECLARATIONS` 里 B2 排在 D 前面，两条都拦时按声明顺序取第一条，
替代话术跟着它走。论证95 那条机制在真链路上兑现了——顺序决定用户看到的话，也决定
哪条规矩的义务被丢掉。

判定对象上栽过一次，记在这里：第一版判的是「本轮最后一条 assistant 消息」，但被拦之后
agent 这一轮还会接着说下一句，最后那条常常不是网关吐出去的那句。改成直接判网关吐出的
字符串，并加了一道自检——那句话必须在会话文本里找得到，20 轮零告警。

**这个数不能当共现率用。** 越界占一半是我造的输入决定的，不是观测到的；未认人也是我
固定的。能带走的是条件结构：**用户这一问越界、且这一轮说话被 B2 拦下时，兜底义务大概率
落空**（5 轮里 4 轮）。真实占比要等真实流量。

## 八、拿闸给候选打分：网关串改得掉，B2 那句改不掉

闸拦下来之后的第一件事不是改措辞，是把候选摆上闸打分
（`check-wording-candidates.ts`，日志 `run-log-wording-candidates.txt`，`repeats=5`）。
7 条候选（含 2 条现状对照），过闸 2 条，全在网关串那一组。

**网关兜底串：真问题，改得掉。** 现状「抱歉，这个问题我需要转人工为您处理。」被 D 判
未兜底——它没说明超出范围或权限。改成「抱歉，这个问题超出我这边能处理的范围，
我帮您转相关部门跟进。」即过闸。**已改**（`check-spec-full.ts` 与 `check-cooccurrence.ts`
两处调用点；这个串不在任何声明里，所以改的是调用点）。冻结闸的失败条数 2/3 → 1/3。

**B2 那句：四条候选全被 D 拦，包括明说了兜底的那条。**

| 候选 | 撞上 |
|---|---|
| 现状「麻烦您先提供一下学号、手机号码，这边为您查询。」 | B2 自己 + D |
| 「为了保护您的账号安全，需要先完成身份核验才能继续。」 | D |
| 「这个我需要先核验您的身份才能答复。」 | D |
| 「…需要先核验身份；若超出我们的服务范围，会转相关部门跟进。」 | D |

两件事分开看：

1. **撞 D 是措辞解决不了的。** B2 的触发条件（未认人 + 要讲账号）既可能出现在范围内提问，
   也可能出现在越界提问；一条固定串要满足 D 就得说「超出范围、已转出」，而那句话在范围内
   的提问下是错的。连条件式的写法（「若超出…会转…」）也被判未兜底——判定器要的是兜底，
   不是备选。**这不是措辞问题，是「一条约束配一条固定替代话术」这个设计在多约束下不够用。**
2. **撞它自己（发现 27）可能是判定器误判。** B2 的 topic 是「具体账号的账期、费用、账号详情」，
   而这句话是**向用户要他自己的学号**，没有泄露任何账号信息。候选 1、2 把字段名拿掉就不再
   自撞——但代价是用户不知道该提供什么。**没改**：那是为评测优化，正是这个项目一直
   避免的事（SPEC 那份声明的开头就写着话术照抄 SOP、不为判定器好判而改写）。
   记成 B2 判定器的一个已知误判方向：「索要身份信息」被算进了「涉及账号详情」。

所以 campus 这份 SPEC 现在仍然过不了闸，剩的那一条是设计缺口，不是没写好的句子。

## 结论与补法

1. ~~替代话术要跟正常话术一样验收~~ **已实现**，见上一节。
2. 「不得声称未发生的动作」**已登记进 `uncovered`**（`spec-declarations.ts`），
   还没变成规矩。登记时写清了它不是表达不了——一条 `semantic-policy` 就写得出来，
   卡在 SOP 原文没有这一条、措辞要客户定。在它变成规矩之前，
   `checkReplacements` 对这一类全绿：检测器测不到没写进去的东西。
3. 顺序敏感写进文档了（`adjudicate` 的 `@returns`）。但**顺序不能当补法**：
   它只决定两条都拦时谁的话术赢；没拦原句的那条根本不参与裁决，替代话术从它面前
   直接过去（论证96：声明在前的约束放行了原句，替代话术照样绕过它，它一次都没看到）。
   所以冻结闸不能只盯顺序。
4. **冻结那一轮现在真的拦**：`check-spec-full.ts` 在替代话术验收不过时抛错（先把各节
   记录打全再判）。判成 error 不是警告，理由是发现 29 七那组数——真 agent 上越界的
   10 轮里有 4 轮兜底义务落空，不是「理论上可能」。
   直接后果：**campus 这份 SPEC 现在过不了自己的闸**（B2 的替代话术撞 B2 自己和 D，
   网关兜底串撞 D）。要交付得先改这两句措辞，那是客户定的事，本轮没动。
5. 运行时让替代话术再过一遍闸——**没做**。发现 27 已经证明替代话术会被自己的规矩拦下，
   所以再过一遍就要先定「拦了之后换什么」的收敛规则，那是设计决定，不是补丁。
