# 发现 06：门控问题弱反馈一轮就解掉，而且是真泛化

承发现 05。那一轮开发 agent 一次修正机会都没用上（公开集第一轮全过，留出集按设计
不进反馈），所以「反馈闭环对门控这个问题有没有用」是空白。这一轮补上。

脚本 `a2-feedback.ts`，评测集 `a2-evals.ts`，实跑输出 `run-log-a2-feedback.txt`，
三版插件 `submitted/a2-feedback-v{1,2,3}.js`。

## 设计

同一个 dev 会话，两级递增反馈，每级之后重判：

- **v1 首版** —— 提示词与发现 05 的 arm on 完全相同，不给反馈。
- **v2 弱反馈** —— 只给留出集的可观测差异（「说的话不应包含 X，实际说出 Y」），
  **不解释原因**，不提门控二字。
- **v3 强反馈** —— 直接陈述机制事实：模型只在词表命中时被调用，词表没覆盖的说法
  根本没被问到。

三组评测集职责分开：

| 组 | 条数 | 用途 |
|---|---|---|
| PUBLIC | 9 | 每版都判，查回归——修正有没有把已经对的弄坏 |
| HELDOUT | 6 | v2 起进反馈。喂过之后它测的是「照差异改」，不是泛化 |
| HELDOUT2 | 6 | 全程不进提示词与反馈。**泛化只看这一组** |

另加一个不依赖静态复查的机械信号：**单条用例耗时**。每句都问模型实测 0.8–1.6 秒，
被门控挡下是 3–5ms。耗时直接读出「这句到底有没有问模型」，阈值取 300ms。

## 结果

| 版本 | 公开集 | 留出集（喂过） | 留出集2（never fed） | 留出集2 未问模型 |
|---|---|---|---|---|
| v1 | 9/9 | 1/6 | 2/6 | 5/6 |
| v2 | 9/9 | 6/6 | 6/6 | **0/6** |
| v3 | 9/9 | 6/6 | 6/6 | 0/6 |

两条要读出来：

1. **v1 复现了发现 05 的形态，而且门控更严**。同样是「写了调模型、又用词表当门控」，
   但这一版留出集 6 条**一条都没问到模型**（含它「通过」的那条过度改写对照——
   不改写自然就过）。加上发现 05 的 arm on，这个形态 n=2 两次都出现。
2. **弱反馈一轮就解掉，并且泛化**。v2 在留出集 6/6 的同时，从没进过任何提示词的
   留出集2 也是 6/6，未问模型 0/6。不是照着喂进去的那 5 句打补丁——是把门控整个拆了。

v3 的强反馈没有带来变化（三组数字与 v2 相同），也没有把已经对的弄坏。

## 拆掉的是什么

v1 的入口：

```js
async function rewriteBlock(text) {
  if (!needsRewrite(text)) return text;   // ← 词表没命中，直接返回，callLLM 不会被调用
  ...
```

v2 把这一行删了，`callLLM` 无条件调用；词表降级成两件事——模型调用抛错或返回
无法解析时的兜底，以及模型判为合规但强禁语字面仍在时的强制覆盖：

```js
raw = await callLLM(text);                         // 每句都问
...
if (parsed.needRewrite === false) {
  if (matchesAny(text, STRONG_PATTERNS)) return fallbackReplace(text);   // 模型漏判时兜底
  return text;
}
if (matchesAny(text, ALL_PATTERNS)) return fallbackReplace(text);        // 解析失败时兜底
```

词表的职责从**分流器**（决定要不要问模型，于是词表的盲区变成整个系统的盲区）
变成**兜底下限**（已知禁语无论如何被清掉，模型挂了也成立），上限交给模型。
两层各管一头，盲区不叠加。

## 与发现 05 合起来说

- 告知这条路存在，模型会走（发现 05）。
- 但它第一版会把新机制挂在旧机制后面，收益被门控抵消（发现 05，n=2）。
- **这个错反馈拦得住，而且只要可观测差异就够，不用告诉它错在哪**（本发现）。

第三条是这一轮唯一的新信息，也是 HANDOFF 里「反馈闭环已实测会静默空转」之外的
另一面：反馈没送达时它空转，送达时它有效。两件事不矛盾——空转是传输问题，
不是反馈内容不够用。本轮三轮反馈全部正常送达，零空转。

## 这一轮没有验的

- 仍然 n=1（这一轮只跑了一次三级序列）。v2 能不能稳定一轮解掉，未知。
- HELDOUT 已污染（v2 起进过反馈），后续实验不能再拿它当留出集。HELDOUT2 目前干净，
  但只要它进过一次反馈就同样作废——留出集是消耗品。
- 拆掉门控后每句都问模型，实测 0.8–1.6 秒挂在说话路径上。这个代价没有做过用户侧评估。
- fail-open 路径（模型调用抛错 → 落回词表）仍然零失败、没走到过、没数据。
  v2/v3 都写了这条分支，都没被执行过。
- 单约束、单插件。多插件下判定协议与用户正文互相污染仍未碰到。
