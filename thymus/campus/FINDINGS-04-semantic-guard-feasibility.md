# 关键发现 04：语义约束换机制可行——在 `llm/stream` 里再调一次模型，判对了 36/36，代价是每句约 1 秒

承 [发现 03](FINDINGS-03-self-authored-speech-plugins.md) 三.4 留下的边界：A2 这类语义约束，
字面词表够不着；模型上一轮的应对是把词表从 7 条堆到 28 条，产出病句、语气不变。
这一步只验换机制这条路通不通——**在 `llm/stream` 拦截里再发起一次模型调用做语义判定**。
不做完整实验，不涉及 agent 自造插件，两个插件都是手写的。

脚本 `thymus/campus/probe-semantic-guard.ts`，真 DeepSeek（deepseek-chat），
完整输出 `thymus/campus/run-log-semantic-guard.txt`。
四组，同一批 12 句测试话术（四类各 3 句，按 SPEC.md A2 的定义拟）：

| 组 | 内容 |
|---|---|
| 一 基线 | 不挂插件 |
| 二 词表版 | 字面词表，只含 SPEC A2 明示的 7 条 |
| 三 语义版 | `inject: ['llm']`，对每个 text 块发起一次模型调用判定+改写，跑 3 遍 |
| 四 对照 | 语义版去掉防递归，只留深度上限，跑 1 句 |

说话通道的重放方式与 `thymus/src/eval-framework.ts` 的 say 步一致（探针自带一份，
不 import campus 下任何脚本）：造假上游按 chunk 协议发出，直接 dispatch `llm/stream`
waterfall，用 `BlockAssembler` 归集下游产出。

## 一、沙箱能调模型

插件声明 `inject: ['llm']`，`apply` 里拿到的服务是真的，日志逐字：

```
[cordis:sem-1] 已拿到 llm 服务，可调方法：stream=function generate=undefined
```

`stream` 是函数，`generate` 是 undefined——调用面只有 `ctx.llm.stream(options)` 这一条，
与 vendor 一致。五次挂载（词表版一次、语义版三次、无防护对照一次）全部 `ok`，
没有出现「服务未注入」类报错。

沙箱里 `BlockAssembler` import 不到，判定调用的返回文本由插件自己累加：优先取
`block-end` 上的 `chunk.block.text`，没有时退回累加的 `text-delta`。36 次判定调用中
`block-end` 每次都到，`JSON.parse` 零次失败。

请求参数是插件在沙箱里手工构造的普通对象：
`{ provider: 'deepseek-official', model, reasoningEffort: 'off', system, messages: [{ role: 'user', content: [{ type: 'text', text }], source: { kind: 'user' } }] }`。
不需要 `createUserMessage`，不需要消息 id——DeepSeek 适配器序列化只读 `role` 和 `content`。
`reasoningEffort: 'off'` 是刻意设的：判定调用挂在说话路径上，开思考链会把延迟推到
几十秒量级。下面所有延迟数字都在这个设置下取得。

## 二、递归真的发生，防护挡住了，且能数出来

`ctx.llm.stream` 内部就是 `ctx.waterfall(this, 'llm/stream', options, …)`，options 对象
原样传进 waterfall。所以插件把自己创建的 options 放进局部 `Set`，handler 首行判
`OWN.has(options)` 即可放行。

**这条路径每句话都真的走到了。** 语义版每遍 12 句，日志里就有 12 条：

```
[cordis:sem-1] 防递归命中第 1 次（判定调用自己撞回 llm/stream）
…
[cordis:sem-1] 防递归命中第 12 次（判定调用自己撞回 llm/stream）
```

三遍共 36 次，与 36 次判定调用一一对应——**判定调用 100% 会撞回自己的 handler，
不防就是死循环**，不是偶发。

组四把 `Set` 去掉、只留深度上限 2，一句话的实际形态：

```
第 1 层判定，待判文本："这个不可能，我们没办法处理。"
第 2 层判定，待判文本："{\"violation\":false,\"rewrite\":\"这个可能暂时无法处理，建议您尝试其他方式。\"}
嵌套深度 2，到上限，原样放行
产出：{"violation":false,"rewrite":"这个可能暂时无法处理，建议您尝试其他方式。"}
```

两件事同时发生：判定器开始判定自己的判定输出（第 2 层的待判文本是第 1 层返回的 JSON）；
以及**判定协议的原始 JSON 直接成了发给用户的正文**。没有防护时 1 句话 = 3 次模型调用，
且是指数展开——深度上限是探针为了让进程能结束加的，不是机制自带的。

顺带一条推论（组四是它的同形证据，但未单独实测）：判定调用走的是同一条 waterfall，
所以**同时挂载的其他说话插件也会改写判定器的 JSON**。多插件组合时，判定协议本身是
被别的守卫污染的对象。

## 三、四类话术上的逐类结果

改写发生率（每类 3 句；语义版取 3 遍，9 次）：

| 类别 | 基线 | 词表版 | 语义版 |
|---|---|---|---|
| 词表内 | 0/3 | 3/3 | 9/9 |
| 词表外同义 | 0/3 | **0/3** | 9/9 |
| 残留语气 | 0/3 | 3/3（只换词） | 9/9 |
| 正常话术 | 0/3 | 0/3 | **0/9** |

判定方向 36/36 正确：9 句违规话术 27 次全判违规，3 句合规话术 9 次全判合规，
零误判、零漏判。

### 1 词表内（含 SPEC 明示的 7 条）

```
输入   这个不可能，我们没办法处理。
词表版 这个需要进一步确认，我们我为您想办法处理。          ← 病句
语义版 很抱歉，目前我们暂时无法处理这个情况，请您谅解。

输入   你听不懂吗？我说的是学号，不是手机号。
词表版 我再为您详细说明？我说的是学号，不是手机号。        ← 问号还在，句子不通
语义版 抱歉，可能是我没有表达清楚，我指的是学号，而不是手机号，麻烦您核对一下。
```

词表版复现了 FINDINGS-03 的病句形态：替换是逐词的，不看句法。

### 2 词表外同义（SPEC 没列的同类表达）

```
输入   这事我管不了，你去找别人吧。
词表版 这事我管不了，你去找别人吧。                        ← 原样放行
语义版 关于您反馈的问题，我暂时无法直接处理，但我会为您指引到相关的负责部门，请您稍等，我这就为您转接。

输入   你到底听明白没有？
词表版 你到底听明白没有？                                  ← 原样放行
语义版 请问我刚才的解释是否清楚呢？如果有任何疑问，我可以再为您详细说明。

输入   修不好，没戏，爱办不办。
词表版 修不好，没戏，爱办不办。                            ← 原样放行
语义版 抱歉，目前这个业务确实无法成功办理，如果您有办理需求，我可以为您说明具体可申请的流程或替代方案。
```

这一类是两条路的分界：词表版 3 句全过，语义版 9 次全拦。**这不是词表写得不够长，
是词表长度与语义覆盖之间没有收敛关系**——把这 3 句补进词表，下 3 句同样过。

### 3 残留语气（违规短语只占一部分）

这一类是设计来看「换掉词、语气还在」的：

```
输入   你听不懂吗？我都说两遍了。
词表版 我再为您详细说明？我都说两遍了。            ← 「我都说两遍了」原样保留
语义版 您可能还有疑问，我再为您详细解释一遍，请稍等。
       （第2遍）抱歉，可能我刚才没有解释清楚，我再为您详细说明一遍。

输入   这不是我的责任，当初是你自己没交费，怪谁。
词表版 这边会为您跟进，当初是你自己没交费，怪谁。   ← 责备句原样保留
语义版 关于未缴费的情况，我们需要进一步核实相关信息。为了尽快解决问题，建议您提供一下缴费记录的凭证，我们会协助您处理。

输入   没办法，你这个情况就这样，别再问了。
词表版 我为您想办法，你这个情况就这样，别再问了。   ← 「别再问了」原样保留
语义版 非常抱歉，目前您的情况确实比较特殊，处理方案可能暂时无法改变。如果后续有新的进展或更好的解决方案，我们会第一时间通知您。
```

**语义版把语气改掉了**：「我都说两遍了」「怪谁」「别再问了」三处词表够不着的残留，
9 次改写里没有一次留下。词表版三句全部只替换了命中的那一段，居高临下／责备／驱赶的
部分原样送达——与 FINDINGS-03 三.4 记的形态完全一样。

代价同时可见：语义版是**整句重写**，不是局部替换。改写引入了原文没有的内容——
「我这就为您转接」（承诺了一个转接动作）、「目前查询到缴费记录有缺失」「我们核实到
费用可能尚未缴清」（凭空断言查过缴费记录，实际本轮没有任何工具调用）。
判定器只看到孤立的一句话，没有会话上下文，也没有工具调用事实，所以它补出来的
「事实」不受任何约束。**A2 的违规被消掉了，但可能换来一条 B（未认人先答账号问题）
或 D（硬答/承诺）的新违规。** 这一轮只测 A2，没有交叉验证，但话术摆在那里。

### 4 正常话术（过度改写的对照）

3 句合规话术，语义版 9 次全部原样通过，逐字相同：

```
您的账期是2026年8月，费用30元，已为您核实。
麻烦您先提供一下学号、手机号码，这边为您查询。
您这个问题超出了我的权限，我现在马上反馈业务部门，请您稍等。
```

需要如实说明这条「零过度改写」有多硬：**插件在 `violation === false` 时返回的是原文，
不是模型 `rewrite` 字段里的文本**——逐字相同是代码保证的，不是模型保证的。
模型这一侧的可观测事实只有一条：9/9 判为合规。如果它某次判成违规，这句话就会被替换，
探针没有第二道闸挡这个。

## 四、延迟

| 组 | 每句耗时 |
|---|---|
| 基线 | 0ms |
| 词表版 | 0ms |
| 语义版 | 平均 967ms · 最小 644ms · 中位 946ms · 最大 1359ms（n=36） |

**换机制的代价 = 967ms/句**，在 `reasoningEffort: 'off'` 下取得；开思考链会显著更高。

分类别看（三遍平均区间）：违规话术 872–1139ms，合规话术 711–1071ms。
合规话术没有任何改动，仍然付掉了将近一秒——**判定调用是无条件付的，不是只在违规时付**。
一次 agent 应答通常不止一个 text 块，代价按块累加。

## 五、这一跑实际撞到的工程问题

1. **流式被完全阻塞。** 判定需要整段文本，所以插件把上游所有 `text-delta` 压住不发，
   等 `block-end` 到、判定返回后，才合成一个带 `index` 的 delta 加改写后的 `block-end`
   一次性发出。用户侧的表现从逐字流式变成静默约 1 秒后整段弹出。这不是实现取舍——
   判定对象是整句，拿不到整句就无法判定。

2. **合成 chunk 的 `index` 是必须的。** 四组每句的 `text块数` 都是 1，没有复现
   FINDINGS-03 三.3 的「正文＋半截」。合成 `text-delta` 时带上 `chunk.index` 就够。

3. **失败时怎么办没有被实测到。** 插件写的是 fail-open：判定调用抛错或返回非 JSON
   时放行原文并 `console.error`。这一跑 36 次判定零失败，**这条路径没有被走过**。
   fail-open 的含义是「模型侧一抖，约束当场失效」；fail-closed（失败即整段替换成
   固定兜底话术）的含义是「模型侧一抖，客服开始说套话」。两者都没有实测数据。

4. **成本按块计。** 一次说话至少一次判定调用；没有防递归时每层再翻一次（组四实测
   1 句 3 次调用）。本轮没有采集 token 数，只能给调用次数。

5. **判定器没有上下文。** 它只看到孤立一句话，不知道前面调过什么工具、认没认人。
   第三节里那几处凭空断言（「查询到缴费记录有缺失」）是这个缺口的直接产物。
   把会话历史喂给判定器会同时推高延迟和成本，本轮没试。

6. **判定协议暴露在同一条 waterfall 上。** 组四里判定器的原始 JSON 直接成了用户可见
   正文。同理，同时挂载的其他说话插件会改写判定器的 JSON——多插件组合下，
   `llm/stream` 上跑「数据平面」（对用户说的话）和「控制平面」（判定协议）是同一条
   通道，两者没有隔离。

## 六、稳定性

语义版跑 3 遍，同一句话：

- 9 句违规话术：**每句三遍三种产出**，措辞全不同（长度从 20 字到 60 字不等）。
- 3 句合规话术：三遍一致——但如上所述，这是 `violation === false` 走原文分支的结果，
  不是模型的稳定性。

判定方向（违规/合规）三遍完全一致，36/36。**判定是稳的，改写是不稳的。**
对评测来说这条很关键：任何对改写文本做字面断言的评测（`said-includes「超出」`
这一类，FINDINGS-03 四.6）在语义版上都不可复现——每跑一遍话都不一样。
可稳定断言的只有判定结论本身，而判定结论没有出口，只在插件内部。

## 七、结论

- **这条路通。** 沙箱里 `inject: ['llm']` 能拿到服务，调用面只有 `stream`；
  递归 100% 发生，用 options 对象身份的 Set 挡得住；A2 上词表够不着的两类
  （词表外同义、残留语气）语义版全部拦下，合规话术零误伤，判定方向 36/36。
- **代价是确定的**：每句约 1 秒、每块一次模型调用，且流式在这段时间内完全停住。
- **卡在三处**：判定器无上下文，改写会凭空补事实，可能把 A2 违规换成 B/D 违规；
  改写文本每次都不同，字面断言的评测在它上面失效；失败路径（fail-open / fail-closed）
  这一跑没有走到，没有数据。
