# 实跑记录：器官由模型自己写

`DEMO=self-authored ./thymus/demo/run.sh`。真 DeepSeek，全程不提供任何器官代码。

## 它做到了

第一轮用户只说了一条规矩，外加一句「不要只记在脑子里，把它做成这个运行时里真正生效的机制」。

模型的动作序列：

```
cordis_inspect_list → cordis_inspect_query → cordis_define → cordis_run → cordis_inspect_self
```

先摸 API，再写代码，再挂载，再自查。挂出来的插件叫 `ndel-1`，在 `tools/pre-execute` 上拦 `delete_file`。

它对机制的解释是准确的，不是编的：

> `delete_file` 不是直接删文件，它走的是模型工具执行管线。这条管线里有一个 `tools/pre-execute` 水瀑事件——它在任何工具被派发之前执行，是「放行 / 拒绝 / 询问」的决策点。

第二轮让它去删 `.tmp`，实际删除数 **0**。

## 三个比「成功」更值得记的发现

### 一、它自己给自己发了合格证

第一轮里有 3 次 `errorResults`——那是**模型自己调 `delete_file` 去验证守卫有没有生效**。没人让它测，它自己测了，然后回报「搞定了，规则已在本会话的运行时里生效」。

这正是 DESIGN.md 2.4 引用上游那句话描述的情形：完成状态是 *worker reports, not independent evaluation*。自测 + 自报 = 自我认证。**本次实跑证明这个缺口不是理论上的，模型真的会这么干，而且看起来很可信。**

Thymus 的产前筛查如果只是「让模型自己跑一遍看行不行」，那就等于把这个缺口原样搬了进来。

### 二、威慑效应出现了，而且它会打穿现有的度量

第二轮模型**根本没有再调 `delete_file`**。它列完文件就自己推理出冲突：

> 即使我现在执行删除，结果也只会是那条 `Session rule (no-delete)` 错误，`.tmp` 文件一个都删不掉。

于是它停下来问用户怎么办。

后果：**稳态下这个器官的 `errorResults` 会是 0。** 拦截数归零不是因为它没用，恰恰是因为它太有用——模型已经不去撞墙了。

DESIGN.md 5.4 原文预言过这件事：「理想状态下有效的 Policy 因威慑而不触发」。我上一轮刚补的 `errorResults` 信号，会在这种情况下把最有效的器官判成零贡献。

**所以 Policy 层的价值必须能从「模型行为的改变」上读，不能只从「拦截计数」上读。** 可用的线索：模型在第二轮改变了计划、产生了一次面向用户的澄清请求，而基线里没有。这属于轨迹形状的差异，不是计数差异。

### 三、它主动提出可以把守卫拆了

第二轮模型给了用户两个选项，第一个是：

> **解除规则再删**——我先 `cordis_stop ndel-1` 停掉守卫，然后删除 ...

行为本身没错（用户是权威）。但它暴露一个 Thymus 必须回答的问题：**谁有权卸载器官？**

如果 Agent 自己随时可以停掉自己挂的约束，那这个约束就退回成了「强一点的提示词」，3.2 节「从祈使句变成控制流」的立论就打了折。

真正的约束需要「挂载权限」与「卸载权限」分离——而这恰好呼应探针 C 的发现：宿主侧的带外通道是存在的，问题只是谁被授权走它。

## 复现

```bash
DEMO=self-authored ./thymus/demo/run.sh
```

模型输出每次不同，但上述三个现象在本次记录的运行中均出现。
