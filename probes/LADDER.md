# Spike 结论：作用域阶梯可行

依据 dsh `99f6f02`（0.1.0-rc.7）。`./probes/run-ladder.sh` 可复现。

## 结论

| 梯级 | 问题 | 答案 |
|---|---|---|
| L1 单会话 | 动态包能不能只影响造它的那个会话 | **能**，需 23 行补丁 |
| L3 全局 | 挂在根上下文的器官是不是真跨会话 | **能**，本来就是 |
| 升降 | 同一个器官能不能在两级之间移动 | **能** |
| L2 preset 层 | 中间那一级 | **未验证** |

## L1：23 行补丁就够

现状是 `cordis-host-runner` 把所有动态包挂在 `rootCtx` 下的一个 `cordis-dynamic` group 里，因此它们的监听器不带作用域标签，对每个 agent 都放行。

补丁（`probes/scope-fix.patch`）做的事：给 runner 加一个 `scopeToSession` 开关（默认 `false`，保持原行为）。打开时，按会话建 `createScope(rootCtx, agent)`，把该会话的 `cordis-dynamic` group 挂在这个带标签的上下文下。

关键在于标签会自然传导：作用域标签沿派生上下文向下继承，而沙箱门面的 `ctx.on` 是直接转发到真实 `ctx` 的（`guard.ts` 里 `Reflect.apply(method, ctx, args)`），所以模型写在沙箱里的监听器拿到的就是带标签的注册。**不需要改沙箱，不需要改 cordis。**

### A/B 实测

同一套 harness、同一段器官源码，只差一个开关：

| | `scopeToSession=false`（现状） | `scopeToSession=true`（补丁） |
|---|---|---|
| 会话 A（挂载方） | 被挡 | 被挡 |
| 会话 B（没挂任何东西） | **也被挡** | **完好** |

对照组：不挂任何器官时两个会话都正常，排除「B 本来就跑不起来」。

### 补丁不破坏现有行为

`cordis-host-runner` 既有 91 个测试，在打了补丁之后全过。开关默认关闭，所以上游行为一字未变。**这个补丁是 PR 形状的，不是本地魔改。**

### 变异测试

把 `createScope(rootCtx, agent)` 换成裸的 `rootCtx`（即不打标签），探针 I 与 K 立刻失败。探针在鉴别，不是空转。

### 顺带证实的一件事

补丁通过 `ctx.agents.get(sessionId)` 取 Agent 当作用域键。这要求取回来的对象与 agent-loop 自己用作作用域键的是**同一个引用**——否则事件准入两边都不匹配，会话 A 也不会被挡。探针里 A 确实被挡了，所以引用是同一个。

## L3 与升降

全局层不需要补丁：把器官作为普通插件挂在根上下文，两个会话都受管。这也正是「转正」之后它应有的形态——不再是沙箱里的动态包。

探针 K 走完了一个完整升降：先挂在 A 的作用域下（B 不受管）→ 卸下、在根上下文挂上（新会话 B2 受管）→ 再卸下（新会话 B3 恢复）。

**同一个器官在两个高度都能挂，且可逆。** 阶梯的骨架成立。

## 没验证的部分（别当成已验证）

**L2（preset 层）没测。** 中间那一级是阶梯里唯一没有实测支撑的。而且已知一条硬约束：preset 只能在空白会话上更换，所以升到 L2 影响的是**之后**开的会话，不是当前这个。

**落盘完全没碰。** L3 那一级我是在进程内直接挂宿主插件，测的是「跨会话」，不是「重启后仍在」。进程内测试测不了重启。落盘是独立的一块工作，和作用域无关。

**「转正」目前不是机制，是两个手动动作。** 探针 K 里的升级是手动卸载再手动挂载。把它变成一个可审查、可回滚的操作，是要设计的东西，不在本次验证范围。

## 复现

```bash
./probes/run-ladder.sh
```

脚本打补丁、拷探针、跑测试（5 个阶梯探针 + 91 个既有测试），跑完全部还原，`vendor/deepseek-harness` 始终停在 rc.7 干净状态。
