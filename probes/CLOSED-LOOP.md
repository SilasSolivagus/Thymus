# Spike 结论：闭环跑通了

一个器官走完 `docs/scope-ladder.svg` 上的全程。依据 dsh `99f6f02`（0.1.0-rc.7）。
`./probes/run-ladder.sh` 可复现（99 个测试：3 个闭环 + 5 个阶梯 + 91 个 dsh 既有）。

## 走过的路

| # | 环节 | 实测结果 |
|---|---|---|
| 1 | 基线 | 三个会话都不受管 |
| 2 | L0 定义 + 通用筛 | 铸号 `guard-1/pkg-1`，定义 ≠ 生效 |
| 3 | L1 单会话 | 只有 A 受管；同 preset 的 B、他 preset 的 C 均不受影响 |
| 4 | 场景筛 | 基线轨迹重放逐条一致，无退化 |
| 5 | L2 preset 层 | A 与 B 同受管，C 不受影响 |
| 6 | 消融验证 | 卸掉则 B 不受管，装回则受管 —— 贡献度非零 |
| 7 | L3 全局层 | 三个会话全部受管，跨 preset |
| 8 | 降级 L3→L2 | C 脱离管辖，A/B 留在观察期 |
| 9 | 降级 L2→L1 | 退回单会话 |
| 10 | 退役 → 档案 | 三个会话全部恢复，档案留源码与到达过的最高层级 |

两条旁路也验了：

- **通用筛拦畸形器官**。语法不合法的在 `define` 当场抛错；语法合法但不返回 plugin 的（`return 42`）拖到挂载才失败，且失败后不残留。**这是两道不同的关，不是一道。**
- **清除**。一个拦一切的器官会把 `cordis_stop` 一并拦下——Agent 自救的唯一手段本身也是工具。宿主侧直接卸载不经工具分发，仍然有效。**带外通道是必需品，不是备选项。**

## 三个关键点

**全程是同一个器官。** L2 / L3 挂载用的模块由 `promote()` 从同一段沙箱源码机械生成（该转换的忠实性由探针 L 单独验过）。不是"另写一个功能相同的插件"。

**三级作用域用的是 dsh 现成的机制。** L1 是 `createScope(rootCtx, agent)`，L2 是 `createScope(rootCtx, standingKeyFor(preset))`，L3 是根上下文。阶梯不是新发明的结构，是踩在 dsh 已有的 `agent → preset → global` 作用域链上。

**升降对称且可逆。** 每一格上去能下来，下来能再上去，全程用同一套 `plugin` / `dispose`。

## 变异测试

把 L2 的挂载键从 `standard` 换成 `minimal`（挂错 preset），闭环立刻断在第 5 步。准入确实是按 preset 键走的，不是碰巧。

## 需要那个补丁

L1 那一格依赖 `probes/scope-fix.patch`（23 行，给 runner 加 `scopeToSession` 开关，默认关闭）。dsh 原有的 91 个 runner 测试在打了补丁之后全过。

## 还没有的东西

**闭环里每一次升降都是测试代码手工调的。** 触发条件、审查逻辑、失败回滚、`cordis.yml` 的增删——一样都不存在。

**场景筛与消融是最小实现。** 场景筛就是重放一条 3 步轨迹比对输出；消融就是卸载前后各测一次。够证明机制走得通，不够当评价体系用。DESIGN.md 第 5 节那套（MAP-Elites、Shapley 值、经验贝叶斯）一点没碰。

**L3 在本闭环里是「挂在根上下文」，不是「重启后仍在」。** 后者由探针 M 单独验证（`boot()` 从磁盘配置起全新的树）。两件事都成立，但不在同一个进程里，所以没法写进同一条闭环。

**preset 层只能在空白会话上更换。** 这条硬约束意味着升到 L2 影响的是之后开的会话。本闭环里三个 agent 都是先建好再挂器官，绕开了这个问题；真实场景里绕不开。
